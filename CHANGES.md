##### DEMO 1 — разделение на ES-модули

Завершено начатое разделение `app.js`. Без сборщика и без изменения логики функций.

## Где что находится

| Файл | Ответственность |
| --- | --- |
| `app.js` | Подключает модули и запускает приложение, сохраняет доступ HTML-обработчиков к нужным функциям |
| `modules/state.js` | Общие данные приложения и названия ключей localStorage |
| `modules/data_loading.js` | Загружает JSON, обновляет экраны и выпадающие списки после загрузки |
| `modules/navigation.js` | Переключает разделы по адресу после `#` |
| `modules/event_listener.js` | Подключает обработчики событий; бывший файл `event_listener` получил расширение `.js` |
| `modules/dashboard.js` | Рисует главную страницу |
| `modules/evidence_list.js` | Каталог улик, фильтры, поиск, сортировка и закладки |
| `modules/evidence_detail.js` | Подробности улики и редактор заметки |
| `modules/people_locations.js` | Люди, места и переключение вкладок |
| `modules/timeline.js` | Хронология и окно быстрого просмотра улики |
| `modules/workspace.js` | Рабочее пространство и форма гипотезы |
| `modules/notes_storage.js` | Чтение и сохранение закладок и заметок |
| `modules/lookup_helpers.js` | Поиск объектов по ID и небольшие функции форматирования |

Границы выбраны по задачам: связанные функции находятся рядом. `populateAllDropdowns`
перенесена в загрузку данных: она обновляет списки сразу нескольких разделов.
Работа формы гипотезы с localStorage оставлена рядом с самой формой.

## Что означают import и export

`export` делает функцию доступной другим файлам. `import` явно подключает её:

```js
// dashboard.js
export function renderDashboard() { /* ... */ }

// navigation.js
import { renderDashboard } from "./dashboard.js";
```

Экспортируются только функции, нужные другим модулям или существующим HTML-обработчикам.
Например, `renderDashboard` публичная, а `statCardHTML` приватная: она нужна только
внутри dashboard.js. Аналогично приватными остались `getFilteredEvidence`,
`renderEvidenceCardHTML`, `statusOptionHTML`, `certaintyBadgeClass`, `getSelectedOptions`
и отдельные шаги загрузки JSON. `latestSearchRequestId` остаётся локальной переменной
модуля списка улик.

Использованы именованные экспорты: имя в импорте показывает, что именно подключается.
При `export default` модуль отдаёт одно основное значение, а импортирующий файл может
выбрать для него любое имя. Здесь default не нужен: многие модули предоставляют
несколько равноправных функций.

## Как модули делят данные

Вместо отдельных глобальных переменных экспортируется один объект:

```js
import { state } from "./state.js";

state.allEvidence = data;           // загрузчик записывает данные
console.log(state.allEvidence);    // другой модуль читает те же данные
```

Браузер выполняет модуль один раз: все импорты получают один и тот же объект.
`const state` запрещает заменить сам объект, но позволяет менять его свойства.
Нельзя написать `state = {}` в импортирующем файле; можно `state.allEvidence = data`.
Не нужно копировать массивы: существующие связи между ними сохранены.
Если забыть импорт `state`, обращение к нему даст `ReferenceError: state is not defined`.
Так ошибка показывает отсутствующую зависимость, вместо неявного обращения к глобальной переменной.

Некоторые модули представлений импортируют друг друга: список открывает детали,
а детали обновляют список. Эти циклы сохранены при минимальном переносе и работают,
потому что функции вызываются после инициализации модулей, а не при их загрузке.

## Чем отличается module-скрипт

В `index.html` теперь стоит `<script type="module" src="app.js"></script>`.
Браузер сам загружает зависимости из import, сборка не нужна.

- Переменные и функции модуля не становятся свойствами `window` автоматически.
- Модуль выполняется после разбора HTML (без атрибута async); обычный скрипт без defer
  выполняется в месте подключения и приостанавливает разбор HTML.
- Внутри модулей автоматически действует строгий режим JavaScript.

Существующие `onclick` и `onchange` в HTML ищут функции вне области видимости модулей.
Поэтому в `app.js` есть явный `Object.assign(window, { ... })` только для семи
нужных обработчиков. Это мост совместимости для чистого рефакторинга; остальные
функции и state не добавляются в window. В дальнейшем inline-обработчики можно
отдельно заменить на addEventListener.

## Как запускать

Из папки проекта:

```sh
python3 -m http.server 8082
```

Открыть `http://localhost:8082`. Если порт занят, выбрать другой свободный порт.
Не открывать index.html через file://: загрузка модулей проверяет origin/CORS,
а локальные файлы не дают обычного HTTP-origin. Загрузка JSON через fetch также
ограничена для file://. HTTP-сервер нужен для обоих механизмов.





## Demo 2 — mutation/reference bug

`filteredEvidence` больше не получает ссылку на исходный массив: загрузчик создаёт
копию через `slice()`. Сортировка выполняется после фильтрации над отдельным массивом
результатов при каждой отрисовке. Это сохраняет исходный порядок `allEvidence`
и выбранный порядок карточек при фильтрации и повторной отрисовке.

## Demo 3 — Promise success and loading state

После успешного чтения `evidence.json` загрузчик снимает `evidenceViewLoading`
до отрисовки карточек. При ошибке также снимается индикатор, но выводится сообщение
о сбое; HTTP-ошибки проверяются через `res.ok`.



## Demo 4 — ошибка только в Console

Навигационный callback читает кнопку через `event.currentTarget`, а не через
общую переменную `var i`, которая после цикла выходила за границы списка.
Переходы проверены многократно: прежнего TypeError больше нет.

## Demo 5 — полный проход и исправления

- Dashboard обновляет счётчики при возвращении и выбирает Recent evidence по дате.
- Смена статуса/relevance не стирает введённую заметку; заметки выводятся как текст.
- Ссылки людей очищают прежние фильтры; Timeline выводит название места.
- Обработчик окна Timeline подключается один раз.
- Чтение localStorage проверяет JSON и типы; закладки очищаются от повторов и неизвестных ID, значение confidence 0 сохраняется.
- Поля гипотезы сохраняются автоматически; ручное сохранение осталось.
- Стартовая навигация ждёт загрузку данных; HTTP-сбои показываются как ошибки.
- Предпросмотр заметки в Console выводит результат Promise, а не сам Promise.

сценарии нет; искусственные сбои диагностируются. Файлы тестов в проект не добавлены.
